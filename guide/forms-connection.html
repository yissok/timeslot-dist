A separate database for Timeslot

Use your computer for this one-time setup. The app can then use the database on your phone with the spreadsheet closed. This POC has public reads and unprotected writes; use dummy names.

  1. Copy the verified sheet-db template. Name the copy Timeslot database. The template already contains the connector source; no script installation is needed.
  2. In your new copy, choose sheet-db → Set up public Forms POC. Approve Google permissions and the public-access prompt. If consent interrupts setup, choose the menu action again. It creates a new Form and background trigger for this copy.
  3. Copy the complete connection JSON from the dialog. Use this new JSON, rather than the original template's connection details.
  4. Open Timeslot, then Connection → Connect database. Paste the JSON and connect. Check that the displayed database is Timeslot database, then choose Use this Sheet. Timeslot creates its own settings, slots and bookings tables.
  5. Close the Sheet and Apps Script tabs. Open Schedule, choose a date and timezone, and create the schedule. In All slots, book 09:00 with a dummy name, refresh to check it persisted, and cancel it.
  6. Reload Timeslot. It should reconnect using saved details and retain the schedule. On your phone, open the same hosted Timeslot app and paste this database's JSON once. Check booking, cancellation and return visits there yourself.

Disconnect and forget removes the remembered connection from this browser. A timed-out write may have completed: keep the page open and use Retry the same change when offered.

A copied template may include old dummy response history. Its setup creates a fresh Form; your current records live in this copy. Deleting current rows does not purge historical Form responses. If setup fails, keep the copy and report the exact error instead of repeatedly making new copies.

If Timeslot still shows Sheet-panel instructions, its Forms update has not been deployed yet. Check the app version after deployment before continuing.
